# Design: дубли отметок «Близость» + история дат

Связано с: `requirements.md` (тот же слаг)

## Решение D1 (из требований, повторён тут кратко)

Никаких миграций схемы. `sex_logs` остаётся как есть, дубли не чистим массово.
Инвариант «один день = одна строка» держим на уровне приложения:
запись — upsert, чтение — схлопывание.

## Слои

### 1. `app/db.py` — хранилище

| Функция | Было | Стало |
|---|---|---|
| `add_sex(user_id, day, protection)` | всегда `INSERT` → дубль | `SELECT id ... ORDER BY id DESC LIMIT 1`; если есть → `UPDATE protection`; иначе `INSERT`. Возвращает `"updated"` / `"created"` |
| `recent_sex(user_id, limit, offset)` | `ORDER BY day DESC, id DESC LIMIT ?` (дубли видны) | `JOIN` по `MAX(id)` на день → одна строка на день. Добавлен `offset` |
| `sex_days_count(user_id)` | — | `COUNT(DISTINCT day)` — всего дней с отметками |
| `delete_sex(user_id, day)` | — | удаляет все строки за день; **вызывается только после явного подтверждения юзером** |

Запросы — чистый ANSI, одинаково идут в SQLite и Postgres (`?` → `$n` конвертирует `_to_pg`).
Никакого `DELETE` по «дублям» и никакого `ALTER` — старые строки лежат нетронутые.

### 2. `app/texts.py` — тексты

- `sex_card(rows, share, total)` — блок «Недавно» (5 шт.) + строка «Всего отметок: N» +
  блок «Партнёр». Если `share` выключен — блока «Партнёр» нет.
- `sex_history_card(rows, total, page, per_page)` — отдельный экран «ВСЯ ИСТОРИЯ»:
  список дат, подпись «Показаны 1–5 из 12».
- `sex_delete_confirm(day_label)` — экран подтверждения отмены.

### 3. `app/keyboards.py` — кнопки

- `sex_when_kb()` — добавляется кнопка **«Вся история»** (`menu:sexhistory`).
- `sex_history_kb(rows, page, has_more, per_page)` — по кнопке «Убрать <дата>» на каждую запись
  (иконка `TRASH`, `style=RED`) + навигация «Показать ещё» / «Показать новые» + «Назад».
- `sex_delete_kb(iso)` — «Да, убрать» / «Отмена».

### 4. `app/handlers.py` — маршруты

| callback | Действие |
|---|---|
| `menu:sexhistory` | `show_sex_history(page=0)` |
| `sexhist:<page>` | `show_sex_history(page)` |
| `sexdel:<iso>` | экран подтверждения отмены |
| `sexdelok:<iso>` | `db.delete_sex` → карточка «Близость» |
| `sexdelno` | назад в историю |

Текстовый хендлер (регистрируется **последним** в файле, чтобы не глотал остальные):
сообщение содержит «посмотреть» / «смотреть» / «истори» / «история» (регистронезависимо) →
ответ-подсказка с кнопкой «Вся история». Проверяем, что FSM-состояние пустое,
чтобы не перехватить заметку дневника.

## Почему отмена с подтверждением

Удаление — необратимо. Одно нажатие «Убрать 18 октября» рядом с «Показать ещё» легко промахнуться.
Поэтому два шага: выбор даты → явное «Да, убрать».

## Поток пользователя (как решается жалоба клиентки)

1. «Близость» → видит последние 5 + кнопка **«Вся история»**.
2. «Вся история» → пагинация по 5, внизу «Показать ещё». Все её даты видны.
3. Дубль 18 октября показан **один раз** (на чтении схлопывается), в базе обе строки целы.
4. Ошибочную дату можно убрать: «Убрать 18 октября» → «Да, убрать».
5. Вопрос текстом «как посмотреть предыдущие» → бот отвечает подсказкой с кнопкой.

## Тесты

`tests/test_db.py`:
- повторная отметка того же дня не создаёт вторую строку;
- смена protection обновляет запись;
- `recent_sex` схлопывает заранее вставленные дубли;
- `sex_days_count` считает дни, а не строки;
- `delete_sex` удаляет за день и не трогает соседние дни.

`tests/test_texts.py`:
- `sex_card` показывает «Всего отметок» и блок партнёра;
- `sex_history_card` содержит диапазон «1–5 из N»;
- при `share=False` блока «Партнёр» нет.

## Границы

- Схема БД не меняется. Миграций нет.
- Расчёт цикла, дневник, партнёр, уведомления — не трогаем.
- Партнёру история близости не отправляется (тот же `share_sex`).
